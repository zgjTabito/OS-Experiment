```C
void proc_run(struct proc_struct *proc)
{
    if (proc != current)
    {
        bool intr_flag;
        struct proc_struct *prev = current;
        
        // 1. 禁用中断
        local_intr_save(intr_flag);
        
        // 2. 更新当前进程
        current = proc;
        
        // 3. 切换页表到新进程的地址空间
        lsatp(proc->pgdir);

        // 3.5. 刷新 TLB，避免旧进程残留的映射影响新进程
        flush_tlb();
        
        // 4. 执行上下文切换
        switch_to(&(prev->context), &(proc->context));
        
        // 5. 恢复中断（在 switch_to 返回后执行）
        local_intr_restore(intr_flag);
    }
    
}
```

`proc_run` 在切换进程时新增 `flush_tlb()`。lab8 引入每进程独立页表和文件系统后，进程切换时要先切 SATP（`lsatp(proc->pgdir)`），再刷新 TLB，避免前一个进程残留的地址映射被误用，保证新进程的虚拟内存映射一致、页缓存不会脏读旧映射。

## 练习一：完成读文件操作的实现（需要编码）

> 首先了解打开文件的处理流程，然后参考本实验后续的文件读写操作的过程分析，填写在 kern/fs/sfs/sfs_inode.c中 的sfs_io_nolock()函数，实现读文件中数据的代码。

完成了 `sfs_io_nolock()` 的核心读写逻辑，遵循“首尾块按偏移处理 + 中间整块直传”的三段式流程。

```C
    blkoff = offset % SFS_BLKSIZE;
    if (blkoff != 0) {
        size = (nblks != 0) ? (SFS_BLKSIZE - blkoff) : (endpos - offset);
        if ((ret = sfs_bmap_load_nolock(sfs, sin, blkno, &ino)) != 0) {
            goto out;
        }
        if ((ret = sfs_buf_op(sfs, data, size, ino, blkoff)) != 0) {
            goto out;
        }
        data += size;
        alen += size;
        offset += size;
        blkno ++;
        if (nblks != 0) {
            nblks --;
        }
    }

    /*
     * (2) Transfer the fully aligned blocks in the middle.
     */
    while (nblks != 0) {
        if ((ret = sfs_bmap_load_nolock(sfs, sin, blkno, &ino)) != 0) {
            goto out;
        }
        size = SFS_BLKSIZE;
        if ((ret = sfs_block_op(sfs, data, ino, 1)) != 0) {
            goto out;
        }
        data += size;
        alen += size;
        offset += size;
        blkno ++;
        nblks --;
    }

    /*
     * (3) Handle the trailing partial block if end position is not aligned.
     */
    if (offset < endpos) {
        size = endpos - offset;
        if ((ret = sfs_bmap_load_nolock(sfs, sin, blkno, &ino)) != 0) {
            goto out;
        }
        if ((ret = sfs_buf_op(sfs, data, size, ino, 0)) != 0) {
            goto out;
        }
        alen += size;
    }
```

- **首个非对齐块**：计算 `blkoff = offset % SFS_BLKSIZE`，若不为 0，先通过 `sfs_bmap_load_nolock` 找到对应物理块号 `ino`，用 `sfs_buf_op` 从偏移 `blkoff` 处读/写 `size` 字节（剩余或全量），再推进指针与计数。
- **中间整块**：循环 `nblks`，每次 `sfs_bmap_load_nolock` 获取块号，再用 `sfs_block_op` 直接整块传输（块大小 `SFS_BLKSIZE`），更新数据指针与累计长度。
- **末尾非对齐块**：若 `offset < endpos`，再次映射块号后调用 `sfs_buf_op` 处理末尾残留字节，完成对齐之外的收尾操作。
- 读写均复用同一逻辑，借助函数指针 `sfs_buf_op`/`sfs_block_op` 在读写模式间切换；结束时把实际传输长度写回 `alen`，并在写入路径下更新文件大小与脏标记。
- 错误处理：任一步 `bmap` 或块操作出错即跳转 `out` 返回错误，已传输长度会通过 `*alenp` 反馈给上层，保证部分成功时可见。

## 练习2: 完成基于文件系统的执行程序机制的实现（需要编码）

>改写proc.c中的load_icode函数和其他相关函数，实现基于文件系统的执行程序机制。执行：make qemu。如果能看看到sh用户程序的执行界面，则基本成功了。如果在sh用户界面上可以执行`exit`, `hello`（更多用户程序放在`user`目录下）等其他放置在`sfs`文件系统中的其他执行程序，则可以认为本实验基本成功。

```c
static int
load_icode(int fd, int argc, char **kargv)
{
    if (current->mm != NULL)
    {
        panic("load_icode: current->mm must be empty.\n");
    }

    int ret = -E_NO_MEM;
    struct mm_struct *mm;
    struct elfhdr elf;
    struct proghdr *ph = NULL;

    /* (1) create a new mm for current process */
    if ((mm = mm_create()) == NULL)
    {
        goto bad_mm;
    }

    /* (2) create a new PDT, and mm->pgdir = kernel virtual addr of PDT */
    if ((ret = setup_pgdir(mm)) != 0)
    {
        goto bad_pgdir_cleanup_mm;
    }

    /* (3.1) read ELF header */
    if ((ret = load_icode_read(fd, &elf, sizeof(struct elfhdr), 0)) != 0)
    {
        goto bad_elf_cleanup_pgdir;
    }
    if (elf.e_magic != ELF_MAGIC)
    {
        ret = -E_INVAL_ELF;
        goto bad_elf_cleanup_pgdir;
    }

    /* (3.2) read program headers */
    size_t phdroff = elf.e_phoff, phnum = elf.e_phnum;
    size_t phentsize = elf.e_phentsize;
    size_t phsize = phnum * phentsize;
    if ((ph = kmalloc(phsize)) == NULL)
    {
        goto bad_elf_cleanup_pgdir;
    }
    if ((ret = load_icode_read(fd, ph, phsize, phdroff)) != 0)
    {
        goto bad_cleanup_ph;
    }

    struct Page *page = NULL;
    uint32_t vm_flags, perm;
    struct proghdr *phe = (struct proghdr *)((char *)ph + phsize);
    struct proghdr *p;

    for (p = ph; p < phe; p++)
    {
        /* (3.4) only load segments */
        if (p->p_type != ELF_PT_LOAD)
        {
            continue;
        }
        if (p->p_filesz > p->p_memsz)
        {
            ret = -E_INVAL_ELF;
            goto bad_cleanup_mmap;
        }

        /* (3.5) setup vma for this segment */
        vm_flags = 0;
        perm = PTE_U | PTE_V;
        if (p->p_flags & ELF_PF_X)
            vm_flags |= VM_EXEC;
        if (p->p_flags & ELF_PF_W)
            vm_flags |= VM_WRITE;
        if (p->p_flags & ELF_PF_R)
            vm_flags |= VM_READ;

        if (vm_flags & VM_READ)
            perm |= PTE_R;
        if (vm_flags & VM_WRITE)
            perm |= (PTE_W | PTE_R);
        if (vm_flags & VM_EXEC)
            perm |= PTE_X;

        if ((ret = mm_map(mm, p->p_va, p->p_memsz, vm_flags, NULL)) != 0)
        {
            goto bad_cleanup_mmap;
        }

        /* (3.6.1) load file-backed part */
        uintptr_t start = p->p_va, la = ROUNDDOWN(start, PGSIZE);
        uintptr_t end = p->p_va + p->p_filesz;
        size_t off, size;

        while (start < end)
        {
            if ((page = pgdir_alloc_page(mm->pgdir, la, perm)) == NULL)
            {
                goto bad_cleanup_mmap;
            }
            off = start - la;
            size = PGSIZE - off;
            if (end < la + PGSIZE)
            {
                size -= la + PGSIZE - end;
            }
            if ((ret = load_icode_read(fd, page2kva(page) + off, size, p->p_offset + (start - p->p_va))) != 0)
            {
                goto bad_cleanup_mmap;
            }
            start += size;
            la += PGSIZE;
        }

        /* (3.6.2) build BSS part */
        end = p->p_va + p->p_memsz;
        if (start < la)
        {
            if (start == end)
            {
                continue;
            }
            off = start - (la - PGSIZE);
            size = PGSIZE - off;
            if (end < la)
            {
                size -= la - end;
            }
            memset(page2kva(page) + off, 0, size);
            start += size;
        }
        while (start < end)
        {
            if ((page = pgdir_alloc_page(mm->pgdir, la, perm)) == NULL)
            {
                goto bad_cleanup_mmap;
            }
            off = start - la;
            size = PGSIZE - off;
            if (end < la + PGSIZE)
            {
                size -= la + PGSIZE - end;
            }
            memset(page2kva(page) + off, 0, size);
            start += size;
            la += PGSIZE;
        }
    }

    /* (4) build user stack memory */
    vm_flags = VM_READ | VM_WRITE | VM_STACK;
    if ((ret = mm_map(mm, USTACKTOP - USTACKSIZE, USTACKSIZE, vm_flags, NULL)) != 0)
    {
        goto bad_cleanup_mmap;
    }
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - PGSIZE, PTE_USER) != NULL);
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - 2 * PGSIZE, PTE_USER) != NULL);
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - 3 * PGSIZE, PTE_USER) != NULL);
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - 4 * PGSIZE, PTE_USER) != NULL);

    /* (5) install mm and switch page table early so copy_to_user works */
    mm_count_inc(mm);
    current->mm = mm;
    current->pgdir = PADDR(mm->pgdir);
    lsatp(PADDR(mm->pgdir));

    /* (6) setup argc/argv in user stack */
    uintptr_t stacktop = USTACKTOP;
    uintptr_t uargv[EXEC_MAX_ARG_NUM];
    int i;
    for (i = argc - 1; i >= 0; i--)
    {
        size_t len = strlen(kargv[i]) + 1;
        stacktop -= len;
        if (!copy_to_user(mm, (void *)stacktop, kargv[i], len))
        {
            ret = -E_INVAL;
            goto bad_cleanup_mmap;
        }
        uargv[i] = stacktop;
    }
    stacktop = ROUNDDOWN(stacktop, sizeof(uintptr_t));
    stacktop -= (argc + 1) * sizeof(uintptr_t);
    uintptr_t argv_base = stacktop;
    if (!copy_to_user(mm, (void *)stacktop, uargv, argc * sizeof(uintptr_t)))
    {
        ret = -E_INVAL;
        goto bad_cleanup_mmap;
    }
    uintptr_t nullp = 0;
    if (!copy_to_user(mm, (void *)(stacktop + argc * sizeof(uintptr_t)), &nullp, sizeof(uintptr_t)))
    {
        ret = -E_INVAL;
        goto bad_cleanup_mmap;
    }
    /* push argc on stack so sp points to argc, argv array follows */
    stacktop -= sizeof(uintptr_t);
    uintptr_t cargc = (uintptr_t)argc;
    if (!copy_to_user(mm, (void *)stacktop, &cargc, sizeof(uintptr_t)))
    {
        ret = -E_INVAL;
        goto bad_cleanup_mmap;
    }

    /* (7) setup trapframe for user environment */
    struct trapframe *tf = current->tf;
    uintptr_t sstatus = tf->status;
    memset(tf, 0, sizeof(struct trapframe));
    tf->gpr.sp = stacktop;
    tf->epc = elf.e_entry;
    tf->status = (sstatus | SSTATUS_SPIE) & ~SSTATUS_SPP & ~SSTATUS_SIE;
    tf->gpr.a0 = argc;
    tf->gpr.a1 = argv_base;

    ret = 0;
    goto out;

bad_cleanup_mmap:
    if (current->mm == mm)
    {
        lsatp(boot_pgdir_pa);
        current->mm = NULL;
        mm_count_dec(mm);
    }
    exit_mmap(mm);
bad_cleanup_ph:
    if (ph != NULL)
    {
        kfree(ph);
        ph = NULL;
    }
bad_elf_cleanup_pgdir:
    put_pgdir(mm);
bad_pgdir_cleanup_mm:
    mm_destroy(mm);
bad_mm:
out:
    if (ph != NULL)
    {
        kfree(ph);
    }
    sysfile_close(fd);
    return ret;
}
```

1) 文件读取链路  
   - 新增 `load_icode_read(fd, buf, len, offset)` 封装 `sysfile_seek`/`sysfile_read`，按偏移读取 ELF 头、程序头及各段数据。  
   - `load_icode` 首先读取 ELF 头并校验魔数，再 kmalloc 程序头数组并读入。  
2) 段映射与加载  
   - 仍对每个 `PT_LOAD` 段创建 VMA（`mm_map`）并计算权限位 `PTE_{R,W,X,U,V}`。  
   - 文件内容部分：逐页 `pgdir_alloc_page` 后调用 `load_icode_read` 把文件数据搬到物理页。  
   - BSS 部分：对文件尾到 memsz 的区域按页 `memset 0`。  
3) 用户栈与参数布局  
   - 先 `mm_map` 用户栈并分配多页。  
   - 提前安装新页表：`mm_count_inc`、`current->mm/pgdir`、`lsatp`，以便 `copy_to_user` 可用。  
   - 从栈顶向下拷贝每个字符串，再放置 argv 指针数组（结尾 NULL），最后压入 argc，使用户态入口看到 `a0=argc`、`a1=argv_base`。  
4) trapframe 设置  
   - 清零 tf，设置 `sp=stacktop`、`epc=elf.e_entry`，`status` 置位 `SPIE` 并清 `SPP/SIE`，寄存器 `a0/a1` 传递参数。  
5) 资源与错误处理  
   - 若已切换到新 mm 失败，恢复 `satp` 到 `boot_pgdir_pa`，`mm_count_dec`，并 `exit_mmap/put_pgdir/mm_destroy`。  
   - 释放 `kmalloc` 的程序头缓冲、关闭 fd。  
6) `do_execve` 侧的适配  
   - 校验 `argc` 范围，使用 `copy_kargv` 把用户 argv 拷到内核缓冲；旧 mm 释放后调用 `load_icode(fd, argc, kargv)`；最后 `set_proc_name`。

```c
int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf)
{
    int ret = -E_NO_FREE_PROC;
    struct proc_struct *proc;
    if (nr_process >= MAX_PROCESS)
    {
        goto fork_out;
    }
    ret = -E_NO_MEM;

    if ((proc = alloc_proc()) == NULL)
    {
        goto fork_out;
    }

    if (setup_kstack(proc) != 0)
    {
        goto bad_fork_cleanup_proc;
    }

    if (copy_mm(clone_flags, proc) != 0)
    {
        goto bad_fork_cleanup_kstack;
    }

    if ((ret = copy_files(clone_flags, proc)) != 0)
    { // for LAB8
        goto bad_fork_cleanup_mm;
    }

    copy_thread(proc, stack, tf);

    bool intr_flag;
    local_intr_save(intr_flag);
    {
        proc->pid = get_pid();
        hash_proc(proc);

        // 只通过 set_links 把新进程挂到 proc_list，并维护关系/计数
        proc->parent = current;
        current->wait_state = 0;
        set_links(proc);
    }
    local_intr_restore(intr_flag);

    wakeup_proc(proc);

    ret = proc->pid;
    
fork_out:
    return ret;

bad_fork_cleanup_mm:
    if (proc->mm != NULL)
    {
        if (mm_count_dec(proc->mm) == 0)
        {
            exit_mmap(proc->mm);
            put_pgdir(proc->mm);
            mm_destroy(proc->mm);
        }
        proc->mm = NULL;
    }
bad_fork_cleanup_kstack:
    put_kstack(proc);
bad_fork_cleanup_proc:
    kfree(proc);
    goto fork_out;
}
```

- 新增文件描述符复制：在复制地址空间后调用 `copy_files(clone_flags, proc)`，支持文件系统语义的继承/共享；失败时跳转到文件专用清理路径。
- 资源回滚完善：新增 `bad_fork_cleanup_mm` 分支，若 mm 引用计数减为 0 则执行 `exit_mmap/put_pgdir/mm_destroy`，并在下游统一释放内核栈/pcb，避免文件复制失败时泄漏。
- 进程关系与等待状态：在持锁区显式设 `proc->parent = current` 且将 `current->wait_state` 清 0，再通过 `set_links` 挂接到全局进程链表，保证 wait/exit 语义正确 。
- 结构化步骤注释与顺序保持：沿用 LAB5 的 7 步流程，但插入了文件复制步骤，并在步骤 5 的持锁区同时做 hash、pid 分配和父子链维护，减少竞态窗口。

## 扩展练习 Challenge1：完成基于“UNIX的PIPE机制”的设计方案

> 如果要在ucore里加入UNIX的管道（Pipe）机制，至少需要定义哪些数据结构和接口？（接口给出语义即可，不必具体实现。数据结构的设计应当给出一个（或多个）具体的C语言struct定义。在网络上查找相关的Linux资料和实现，请在实验报告中给出设计实现”UNIX的PIPE机制“的概要设方案，你的设计应当体现出对可能出现的同步互斥问题的处理。）

- 数据结构  
  - `struct pipe_ring { char *buf; size_t size; size_t rpos; size_t wpos; size_t data; };` 固定大小环形缓冲。  
  - `struct pipe { struct pipe_ring ring; int readers; int writers; bool closed_read; bool closed_write; struct semaphore empty; struct semaphore full; struct mutex lock; wait_queue_t rq_readers; wait_queue_t rq_writers; };` 引用计数与同步元数据。  
  - `struct file` 扩展：增加 `enum file_type { FT_REG, FT_DIR, FT_PIPE, ... }; void *private;` 指向 `struct pipe*`；读写/关闭回调指向 pipe 实现；`int flags; off_t off;` 其中 off 对 pipe 忽略。  
  - `struct files_struct` 复用，fork/dup 时共享同一 `struct pipe*`，并调增 readers/writers。

- 关键接口（语义流程）
  1) `int sys_pipe(int fd[2]);`  
     - 分配 `pipe` 与缓冲；读端 file 只读，写端 file 只写；`readers=1, writers=1`；返回两个 fd。失败释放已分配资源。
  2) `ssize_t pipe_read(struct file *f, void *buf, size_t len);`  
     - 非法（写端读）→ `-EINVAL`。  
     - 进入循环：持 `lock` 检查 `ring.data`。  
       - `ring.data==0 && writers>0 && !O_NONBLOCK`：释放锁，睡眠于 `rq_readers`，被唤醒后重试。  
       - `ring.data==0 && writers>0 && O_NONBLOCK`：返回 `-EAGAIN`。  
       - `ring.data==0 && writers==0`：返回 0（EOF）。  
     - 读 `n=min(len, ring.data)`，更新 `rpos/data`，释放锁，`up(&empty)` 或唤醒 `rq_writers`。
  3) `ssize_t pipe_write(struct file *f, const void *buf, size_t len);`  
     - 非法（读端写）→ `-EINVAL`。  
     - 若 `readers==0`：返回 `-EPIPE`（可选发送 SIGPIPE）。  
     - 循环：持 `lock` 检查空闲空间。  
       - 满且有读者且阻塞：释放锁，睡眠 `rq_writers`，被唤醒重试。  
       - 满且非阻塞：返回 `-EAGAIN`。  
       - 有空间：写 `n=min(len, free)`，更新 `wpos/data`，释放锁，`up(&full)` 或唤醒 `rq_readers`。  
  4) `int pipe_close(struct file *f);`  
     - 持锁：若读端关闭则 `readers--/closed_read=true`，写端对称。  
     - 任一端计数归零后唤醒对端等待队列：写端关后唤醒读者（令其读到 EOF）；读端关后唤醒写者（令其得到 `-EPIPE`）。  
     - `readers==0 && writers==0` 时释放缓冲与 `pipe`。  
  5) 选配  
     - `int pipe_poll(struct file *f, struct poll_table *pt);` 报告可读/可写/挂断；注册等待队列。  
     - `int pipe_ioctl(...)` 维护 `FIONREAD` 等。  
     - `ssize_t pipe_splice(...)` 可选零拷贝。

- 同步/互斥策略  
  - 统一用 `lock` 保护 `ring` 元数据和计数。  
  - 睡眠前释放锁，唤醒后重新加锁并重检条件（循环等待队列模式）。  
  - `empty/full` 信号量或等待队列用于阻塞读写；支持 `O_NONBLOCK` 快速返回。  
  - 关闭时必须唤醒对端，避免永久阻塞。中断上下文不进入阻塞路径。

- 生命周期与 fork/dup  
  - `sys_pipe` 分配 `pipe` 与 `buf`（可设为 PGSIZE 或 PIPE_BUF）。  
  - `dup/fork`：共享同一 `pipe*`，根据读/写端类型调增 `readers/writers`。  
  - `pipe_close` 负责计数递减与最终释放。

- 错误语义  
  - 空读且写端关闭：0。空读阻塞：睡眠；非阻塞：`-EAGAIN`。  
  - 满写且读端关闭：`-EPIPE`。满写阻塞：睡眠；非阻塞：`-EAGAIN`。  
  - 端向错误操作：`-EINVAL`。

## 扩展练习 Challenge2：完成基于“UNIX的软连接和硬连接机制”的设计方案

> 如果要在ucore里加入UNIX的软连接和硬连接机制，至少需要定义哪些数据结构和接口？（接口给出语义即可，不必具体实现。数据结构的设计应当给出一个（或多个）具体的C语言struct定义。在网络上查找相关的Linux资料和实现，请在实验报告中给出设计实现”UNIX的软连接和硬连接机制“的概要设方案，你的设计应当体现出对可能出现的同步互斥问题的处理。）

- 核心数据结构（示例）
  - `enum inode_type { I_REG, I_DIR, I_SYMLINK, ... };`
  - `struct inode { uint32_t i_nlink; enum inode_type i_type; size_t i_size; struct super_block *sb; struct inode_ops *i_op; struct file_ops *f_op; struct mutex i_lock; union { struct { char inline_path[SYMLINK_INLINE_MAX]; size_t len; blockno_t ext_block; } sl; }; ... }`
  - `struct dentry { char name[MAX_NAME]; struct inode *inode; struct dentry *parent; int flags; struct mutex d_lock; /* DENTRY_NEGATIVE 等 */ };`
  - inode 持久化：磁盘 inode 增加 `nlink`、`type`、可选内联 symlink 目标与/或块号；目录项格式仍为 `name + inode_no`。

- 关键 VFS 接口（inode_ops 扩展）
  - `int (*link)(struct dentry *old_d, struct inode *dir, struct dentry *new_d);` // 创建硬链接
  - `int (*unlink)(struct inode *dir, struct dentry *d);` // 删除目录项，递减 nlink
  - `int (*symlink)(struct inode *dir, struct dentry *d, const char *target);` // 创建软链接 inode 并写入目标路径
  - `int (*readlink)(struct dentry *d, char *buf, size_t buflen);` // 读取软链接目标
  - `struct dentry *(*lookup)(struct inode *dir, const char *name);` // 遇到 symlink 可返回对应 dentry
  - file_ops：symlink 通常只需 `readlink`，常规 read/write/exec 不直接作用于 symlink 本身。

- 系统调用语义
  - `int sys_link(const char *oldpath, const char *newpath);`
    - 解析 oldpath（跟随 symlink）得到 `inode_src`；解析 newpath 的父目录；父目录加锁并确保目标名不存在；锁定 `inode_src`；写入新目录项指向同一 inode；`i_nlink++` 同步持久化；禁止对目录建硬链（除非特权）。
  - `int sys_unlink(const char *path);`
    - 解析父目录 + 基名，最后一跳可受 `O_NOFOLLOW` 控制；加锁父目录，找到目录项；若目标是目录则拒绝（用 rmdir）；锁定目标 inode，删除目录项，`i_nlink--`；若降到 0 且无打开引用，回收数据块与 inode。
  - `int sys_symlink(const char *target, const char *linkpath);`
    - 解析 linkpath 父目录；创建新 inode `I_SYMLINK`，`i_nlink=1`；将 target 文本写入内联或数据块；插入目录项。
  - `ssize_t sys_readlink(const char *path, char *buf, size_t buflen);`
    - 不跟随最后一跳；读取 symlink 目标文本，最多拷贝 buflen。

- 路径解析（namei）
  - 默认跟随 symlink；支持 `O_NOFOLLOW`（或 open 标志）控制最后一跳不跟随。
  - 维护跳数上限（如 40），超限返回 `-ELOOP` 以防循环。
  - 遇到 `I_SYMLINK`：在持有 `inode->i_lock` 时读取目标字符串，释放锁后拼接剩余路径并重新解析。
  - 目录项缓存需在增删后失效/更新。

- 同步/锁顺序
  - `i_lock` 保护 inode 元数据：`i_nlink`、`i_size`、symlink payload。
  - 目录变更：先锁父目录（或 dentry 锁），再锁目标 inode，固定顺序避免死锁。
  - `link/unlink/symlink` 中，目录项写入/删除与 `i_nlink` 更新在同一临界区；失败需回滚计数。
  - Path walk 读路径时可用目录读锁；修改时升级为写锁；避免长持锁跨越读文件内容。
  - 并发场景：同名创建/删除需互斥；回收 inode 前确保无打开文件且 `nlink==0`。

- 流程摘要
  - 硬链接：walk old → inode；walk new 的父目录→锁父→查重→锁 old→写目录项→`nlink++`→落盘。
  - 解除硬链接：walk 父→锁父→查目标→锁目标→删目录项→`nlink--`；如 0 且无引用，truncate/free。
  - 软链接：walk 父→锁父→创建 inode(type=symlink,nlink=1)→写入 target→插入目录项。
  - 读软链接：walk 不跟随最后一跳→锁 symlink inode→拷贝目标→返回。

- 校验与限制
  - `SYMLINK_MAX` 长度检查；创建/删除在只读 FS 上返回 `-EROFS`。
  - 硬链到目录默认拒绝；权限检查需覆盖源 inode、目标父目录。
  - 循环解析检测（跳数）；错误返回 `-ELOOP`。

- 落盘与一致性
  - 磁盘 inode 扩展字段保持与内存 inode 对齐；目录项格式无需变更。
  - 支持写回或日志化（如有 journaling）以保证 `dirent` 与 `nlink` 原子性；无日志时在同一锁域内先写目录项再写 inode（或反之并带回滚）。

- 可能的扩展/优化
  - symlink 内联存储：短路径放入 inode，长路径落到数据块减少空间浪费。
  - namecache + RCU 读、写路径用互斥锁；若实现复杂可先使用简单 per-dir 互斥。
